# Публичный каталог гостя (Public Listing Contract)

Правило архитектуры (не таблица в БД): **гостевые** списки, поиск и карточки листинга строятся из **read-модели поиска** (документ edge / Typesense / согласованный SQL fallback), а не произвольного чтения OLTP.

## Инварианты

1. **Канон для гостя:** выдача маркетплейса (в т.ч. `GET /v1/specialists` в indexed-режиме) — из **документа листинга** (см. ADR [marketplace-offerings-search.md](marketplace-offerings-search.md), коллекция listing edges).
2. **OLTP (Prisma `Specialist` / `Organization` / offerings)** — источник правды для **кабинета** и команд; гость не должен зависеть от «случайного» прямого SQL к сырым таблицам без контракта витрины.
3. **Теневая проекция** `SearchDocumentProjection` и внешний индекс обновляются через **outbox / единый путь записи** (см. комментарий в `SearchProjectionShadowService`); не дублировать «тихие» `upsert` из разных мест без аудита.

## Исключения

- Легитимный **SQL directory** для фильтров, которые ещё не в индексе (например `bodyZoneSlugs`), при условии что правила витрины совпадают с ADR.
- Публичные **GET одной сущности** (карточка) могут собираться из OLTP, если контракт ответа **явно** совпадает с тем же снимком, что попадает в индекс (без второй логики сортировки).
